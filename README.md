# Haggle (Dead REPO)

Type in a bill you're overpaying on. Get the exact words to say on the phone to lower it.

Haggle writes you a negotiation script — who to ask for, how to get past the phone menu to them, what to open with, what to say when they push back, and how to get the new rate confirmed in writing. You make the call yourself and keep everything you save.

Built for the [RevenueCat Shipaton 2026](https://revenuecat-shipaton-2026.devpost.com/) Next Gen award.

## Why this exists

Every bill-negotiation service on the market — BillShark, BillCutterz, Trim, Experian BillFixer — negotiates on your behalf and takes **30–50% of your savings**, or bundles the service into a paid membership. They're done-for-you services.

Nobody sells the other thing: a cheap flat-rate tool that does the homework and hands it to you. If you save $30 a month on your internet bill, you keep all $360 of it.

## The interesting engineering decision: no LLM

The obvious way to build this in 2026 is an API call to a language model. Haggle deliberately doesn't. Scripts are generated by a local, deterministic rules engine in [`lib/scriptEngine.ts`](lib/scriptEngine.ts) that never touches the network.

That wasn't an AI-avoidance compromise. It's load-bearing:

- **The API key problem.** This repository is public. A client-embedded key is extractable by anyone; a backend proxy means running and paying for a second system.
- **The business model problem.** Premium promises *unlimited* scripts. With per-call inference costs, every power user erodes the margin. A local engine costs zero per script, forever — which is the only reason "unlimited" is honest.
- **The demo problem.** The script result is the product's most important moment. A network call can hang, rate-limit, or return generic waffle. This engine returns in under a millisecond, offline, and produces byte-identical output for the same input every time — which is also what makes it testable.

The craft went into the composition instead of the prompt:

- **A researched provider dataset** ([`lib/providers.ts`](lib/providers.ts)) — the real department name to ask for at each company, since they genuinely differ, plus the phone-menu phrase that routes you there and category-correct vocabulary. Load-bearing facts cite their source in comments.
- **Five tactic families** — a competitor quote, long tenure, a rate increase, insurance shopping, or no leverage at all produce *structurally different* scripts, not one skeleton with the nouns swapped. Insurance is its own family entirely, because insurance pricing doesn't respond to retention-department pressure the way telecom does.
- **Computed numbers** — the target ask is derived from the bill and the category's realistic range, never hardcoded.
- **Deterministic phrasing variation** — several alternates per slot, chosen by a stable hash so output isn't visibly templated but stays perfectly reproducible. `Math.random()` appears nowhere.

56 unit tests cover every category × tactic combination, the ask arithmetic, determinism, and that insurance vocabulary never leaks into a telecom script.

An LLM layer for personalization is a post-hackathon idea, not a gap.

## Monetization

RevenueCat powers a single `premium` entitlement.

Your **first script is completely free** — the whole thing, not a preview. You feel the product work before anything asks you for money. Premium unlocks additional bills, renegotiation reminders (rates quietly creep back up after 12 months), and a self-reported savings tracker.

The paywall is hand-built in [`app/paywall.tsx`](app/paywall.tsx) rather than configured remotely, so its design lives in this repository like everything else.

## Running it

```bash
npm install
cp .env.example .env     # add your RevenueCat key
npm start
```

Most of the app runs in Expo Go. The purchase flow needs a development build, because `react-native-purchases` contains native code:

```bash
eas build --platform android --profile development
```

RevenueCat setup: create a project, add a **Test Store** app, create an entitlement with the exact identifier `premium`, attach products to an offering, and put the `test_` key in `.env`. The Test Store simulates purchases with no App Store or Play Console account.

```bash
npm run typecheck
npm test
```

## Layout

```
app/        screens (expo-router)
components/ design-system primitives, including the Spine
lib/        script engine, provider data, storage, purchases, notifications
theme/      locked color and type tokens
docs/       the design system and product spec these were built against
```

`docs/design-system.md` and `docs/product-spec.md` are the actual specifications the code was written against, kept in the repo rather than thrown away.

## Honesty

Savings figures are sourced ranges of what comparable callers have negotiated — never a promise about your bill. The savings tracker is self-reported: what you told Haggle you were paying, minus what you told it you now pay. Nothing is verified or projected.

Scripts are generated on your device. There's no account, no server, and no bill data leaves your phone.
